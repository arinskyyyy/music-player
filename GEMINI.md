# Workspace Rules

## Git Commit Granularity
- **Never bundle unrelated or multi-part changes into a single commit.**
- Split work into small, focused, meaningful commits—one logical change, feature, fix, or component/module per commit (e.g., separate commits for database/model updates, API endpoints, WebSocket/hook logic, individual UI components, and styles).
- Take as many commits as needed so each commit has a clear, single-purpose commit message before pushing to the remote repository.
- Never create empty or meaningless commits just to increase commit count; every commit must represent a real, meaningful change.
